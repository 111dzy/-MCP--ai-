# 参数化安装底板：用 MCP 把自然语言变成可编辑的三维模型

**赛道：FreeCAD　｜　作品类型：MCP 工具链 + 参数化 CAD 工程　｜　版本：v1.0（初赛）**

> 一句话说明：用户对 AI 说一句"做一块 120×60×10、四角 M4 通孔、R3 圆角的底板"，
> AI 通过 MCP 协议驱动 FreeCAD 完成参数化建模，并在无界面模式下自动导出 STL / STEP /
> 可编辑的 FCStd，全过程留痕、可复现、可验证。

## 一、我们要解决的问题

传统 CAD 建模的门槛不在"画"，而在三件事：

1. **参数化程度依赖人工经验**。改一个尺寸要重新找特征、重算草图、处理约束报错。
2. **模型与文档脱节**。交出去的是 STL/STEP 这类"死"文件，评审或同事无法追溯某个孔为什么在 ±50 mm。
3. **AI 与 CAD 之间没有标准接口**。多数"AI 建模"演示只是让大模型生成一段脚本，没有协议层的调用记录，无法审计。

本作品把这三件事串成一条闭环：**自然语言 → MCP 工具调用 → FreeCAD 参数化特征树 → 标准格式导出 → 结构化日志与校验报告**。

## 二、总体方案

系统由四层组成，每一层都可独立替换：

| 层 | 组件 | 版本 / 作用 |
|---|---|---|
| 交互层 | Cherry Studio | 2.2.2，对话式入口，支持 MCP 服务器管理 |
| 模型层 | DeepSeek-V4.1-Flash | 负责意图理解、参数抽取、工具选择 |
| 协议层 | freecad-mcp（stdio） | 0.1.32，暴露 18 个工具，MCP SDK 1.30.0 |
| 执行层 | FreeCAD 1.1.4 | PartDesign 参数化建模，FreeCADCmd 无界面执行 |

调用路径：

```
用户自然语言
   ↓  (对话)
DeepSeek 选择 execute_code_headless 工具
   ↓  (MCP / JSON-RPC 2.0 over stdio)
freecad_mcp  →  FreeCADCmd.exe 独立进程
   ↓  (Python API)
PartDesign 特征树 + Spreadsheet 参数表
   ↓
bracket.FCStd / bracket.step / bracket.stl / build_report.json
```

**为什么选 headless 而不是 GUI**：`execute_code_headless` 每次调用启动独立的 FreeCADCmd 进程，
不依赖桌面环境、不受界面状态干扰，适合自动化与视频演示；GUI 模式则用于人工检查特征树。
两种模式共用同一份脚本与参数表。

## 三、作品本体：参数化安装底板

### 3.1 几何定义

| 参数 | 数值 | 说明 |
|---|---|---|
| 长度 length | 120 mm | X 方向 |
| 宽度 width | 60 mm | Y 方向 |
| 厚度 thickness | 10 mm | Z 方向 |
| 圆角 corner_radius | R3 | 4 条竖直棱 |
| 孔径 hole_diameter | Ø4.5 mm | M4 螺栓通孔（标准间隙孔） |
| 孔位 hole_dx / hole_dy | ±50 / ±20 mm | 相对板中心 |

### 3.2 可编辑性：模型不是"死"的

FCStd 内部是一棵真正的 PartDesign 特征树，而不是导入的实体：

```
Body
├── BasePlate        AdditiveBox      Length/Width/Height 由参数表驱动
├── CornerFillet     Fillet           Radius 由参数表驱动
├── M4_Hole_1        SubtractiveCylinder
├── M4_Hole_2        SubtractiveCylinder
├── M4_Hole_3        SubtractiveCylinder
└── M4_Hole_4        SubtractiveCylinder
Params               Spreadsheet      所有尺寸单元格带别名
```

每个特征的尺寸、草图位置都写成表达式（例如 `Params.length / 2 - Params.hole_dx`）。
**在 FreeCAD 里改参数表的一个数字，整块板连同孔位、圆角一起重算**，不需要改代码。
我们做了实测：把厚度从 10 mm 改成 15 mm，重算后体积从 71 286.571 mm³ 精确变为
106 929.856 mm³，比值 1.500000。

### 3.3 一键重建

参数存在 `params.json`，脚本 `build_bracket.py` 读取参数、建模、校验、导出、写报告。
两种运行方式等价：

```bash
# 方式一：直接调用 FreeCAD（离线复现）
D:\FreeCAD\bin\FreeCADCmd.exe D:\mcp-cup\project\bracket\build_bracket.py

# 方式二：走 MCP，与 AI 调用完全相同的链路（带完整日志）
python D:\mcp-cup\tools\run_via_mcp.py
```

## 四、结果与验证

### 4.1 几何结果

| 指标 | 结果 | 校验方式 |
|---|---|---|
| 体积 | **71 286.571 mm³** | FreeCAD 实体计算 + STL 网格积分 71 287.98 mm³（差 0.002%，三角化误差） |
| 理论体积 | 71 286.571 mm³ | 72 000 − 636.17（4 孔）− 77.26（4 圆角） |
| 表面积 | 18 371.296 mm² | FreeCAD |
| 拓扑 | 14 个面 / 36 条边 / **1 个实体** | `Shape.isValid() == True` |
| 包围盒 | 120.000 × 60.000 × 10.000 mm | STL 独立解析 |
| 网格 | 876 个三角面 / 43 884 字节 | 二进制 STL 头校验 |

理论值与实体值**完全一致（误差 0.000%）**，说明建模链路没有几何缺陷。

### 4.2 参数化验证

| 测试 | 输入变化 | 期望体积 | 实测体积 |
|---|---|---|---|
| 默认参数 | — | 71 286.571 | 71 286.571 |
| 改圆角与孔径 | R3→R5，Ø4.5→Ø6 | 70 654.425 | 70 654.425 |
| GUI 内改厚度 | 10→15 mm | 106 929.857 | 106 929.856 |

三次结果与解析计算逐位吻合，证明"改参数即可重建"不是宣传口径，而是可重复的工程事实。

### 4.3 MCP 调用记录

每次通过 MCP 构建都会生成两份证据：

- `logs/mcp_call_<时间戳>.jsonl`：完整 JSON-RPC 双向帧，包括 `initialize`、
  `notifications/initialized`、`tools/list`、`tools/call` 与全部响应；
- `logs/mcp_call_<时间戳>.summary.json`：服务器信息、18 个工具清单、调用参数、
  脚本 SHA-256、构建结果。

本次实测记录：服务器 `FreeCADMCP 1.30.0`，协议 `2025-06-18`，工具数 18，
调用 `execute_code_headless` 返回 `isError = false`。

## 五、为什么这是一个"MCP 作品"，而不是"AI 画图"

1. **协议真实**。工具调用走标准 MCP stdio 传输，日志里能看到完整的 JSON-RPC 请求与响应，
   可以逐帧核对，不依赖任何"我调用了"的口头声明。
2. **能力可枚举**。服务器暴露 18 个工具（建模、查询、视图、FEM 等），
   本作品使用的是通用代码执行通道，换一个零件只需换参数与脚本，工具链不变。
3. **结果可验证**。体积、拓扑、包围盒、哈希、导出的三种格式彼此独立校验，
   任何一环造假都会对不上。
4. **失败可诊断**。我们踩过并记录了真实问题：MCP Python SDK 2.x 与 freecad-mcp 不兼容、
   客户端把参数当整串传递导致 `Connection closed`。最终用固定参数的 launcher 解决，
   并把方案写进了复现文档。这部分工程细节本身就是作品价值。

## 六、复现步骤（评审可照做）

1. 安装 FreeCAD 1.1.x 到任意目录，记下 `FreeCADCmd.exe` 路径。
2. 创建 Python 虚拟环境，执行：`pip install "mcp[cli]<2" freecad-mcp==0.1.32`。
3. 把 `freecad_mcp_launcher.py` 中的 `FREECADCMD` 改成本机路径。
4. 在 MCP 客户端中注册服务器：

```json
{
  "mcpServers": {
    "freecad": {
      "command": "<venv>\\Scripts\\python.exe",
      "args": ["D:\\mcp-cup\\tools\\freecad_mcp_launcher.py"]
    }
  }
}
```

5. 运行 `python tools/run_via_mcp.py`，或在对话中要求模型调用
   `execute_code_headless`，得到与本作品一致的体积与拓扑。
6. 用 FreeCAD 打开 `bracket.FCStd`，修改 `Params` 表中的任意数值并重算，
   观察模型与体积同步变化。

## 七、边界与下一步

**当前边界**

- 作品聚焦"单一零件 + 参数化"闭环，尚未覆盖装配体与工程图。
- 特征树目前由脚本生成，尚未接入 FreeCAD 的 GUI 草图交互录制。
- 失败重试策略较简单，复杂零件需要更细的任务拆解。

**决赛计划**

1. 增加装配体：底板 + 立柱 + 连接件，用 MCP 完成配合与干涉检查。
2. 接入 `run_fem_analysis`，对底板做静力分析，输出应力云图并与选型挂钩。
3. 提供网页端参数面板，非 CAD 用户改尺寸即可得到新模型与报价。
4. 完善日志回放：把一次成功构建压缩成可审计的"构建指纹"。
